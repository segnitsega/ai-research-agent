# 05. API Specification

Base path: `/v1`. JSON everywhere except the SSE stream. The OpenAPI document generated by FastAPI is committed at `apps/api/openapi.json` and drives the frontend types (`make types`). A CI check fails if it drifts.

## 1. Conventions

- **Auth:** header `X-API-Key: <key>` on every route except `/healthz` and `/readyz`. Compared in constant time. Missing/invalid returns 401.
- **User:** v1 maps the key to the seeded user `00000000-0000-0000-0000-000000000001`. All data access is scoped by `user_id` already, so real auth can be added later without schema changes.
- **Errors:** RFC 9457 `application/problem+json`: `{ "type", "title", "status", "detail", "instance", "errors"? }`.
- **IDs:** UUID strings. **Timestamps:** ISO 8601 UTC.
- **Pagination:** cursor-based: `?limit=20&cursor=<opaque>` returns `{ "items": [...], "next_cursor": "..." | null }`.
- **CORS:** only `CORS_ORIGINS`. In the default deployment only the Next.js server calls the API, so CORS is mostly irrelevant.
- **Rate limits:** `POST /v1/runs`: 10 per minute per key; concurrent active runs per user: `MAX_ACTIVE_RUNS_PER_USER` (default 2) else 429.

## 2. Endpoints

| Method | Path | Description |
|---|---|---|
| POST | `/v1/runs` | Create and start a run. Body: `RunRequest`. Returns **202** `RunSummary` |

| GET | `/v1/runs/{id}` | `RunDetail`: summary + plan + report (if done) + usage + budget |

| DELETE | `/v1/runs/{id}` | Delete run and its findings/events. 204 |
| GET | `/v1/runs/{id}/sources` | Sources used with status and cache flag |
| GET | `/v1/runs/{id}/findings` | Findings, filter `status`, `sub_question_id` |
| GET | `/v1/runs/{id}/report.md` | Report rendered as Markdown with a references list |
| POST | `/v1/runs/{id}/feedback` | Body: `{ rating?: 1-5, comment?: string, flagged_finding_ids?: string[] }` |

|---|---|---|

| Method | Path | Description |

## 3. SSE stream: `GET /v1/runs/{id}/events`

- `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`.
- Each message:
  ```
  id: <seq>
  event: <type>
  data: <JSON RunEvent>

  ```
- Honors the `Last-Event-ID` header (and `?after=<seq>` query param) by replaying persisted events with `seq` greater than it, then switching to live events with no gaps or duplicates (subscribe to the bus first, then replay, then dedupe by `seq`).
- Sends a comment line `: keep-alive` every 15 seconds.
- Closes the stream after sending a terminal event (`run.completed`, `run.failed`, `run.cancelled`). For an already-finished run it replays everything and then closes.
- Unknown run returns 404; run belonging to another user returns 404.

### Envelope

```json
{
  "seq": 17,
  "run_id": "…",
  "ts": "2026-10-25T16:48:12.331Z",
  "type": "finding.extracted",
  "agent": "reader",
  "data": { }
}
```

## 4. Event catalog

Every event has a Pydantic model in `workflow/events.py`, combined in a discriminated union on `type`. OpenAPI must expose the union so the frontend gets exact types.

| type | agent | data fields |
|---|---|---|
| `run.started` | system | `question`, `depth`, `budget`, `use_memory` |
| `memory.recalled` | system | `preferences: string[]`, `episodes: string[]`, `prior_findings: int` |
| `plan.created` | planner | `plan: ResearchPlan` |
| `iteration.started` | system | `iteration`, `max_iterations`, `focus_sub_question_ids` |
| `search.started` | searcher | `sub_question_id`, `query` |
| `source.found` | searcher | `source_id`, `url`, `title`, `domain`, `sub_question_id`, `reason`, `expected_quality` |
| `source.fetched` | system | `source_id`, `url`, `chars`, `from_cache`, `fetched_at` |
| `source.failed` | system | `source_id?`, `url`, `reason` (`blocked_ssrf`, `timeout`, `http_error`, `too_large`, `unsupported_type`, `robots`) |
| `finding.extracted` | reader | `finding_id`, `source_id`, `sub_question_id`, `claim`, `evidence_quote`, `confidence`, `stance` |
| `finding.rejected` | reader | `source_id`, `sub_question_id`, `claim`, `reason` |
| `critic.review` | critic | `review: Review` |
| `iteration.completed` | system | `iteration`, `accepted_findings_total`, `decision` (`continue`, `write`) |
| `report.started` | writer | `findings_used` |
| `report.completed` | writer | `report: Report` |
| `memory.updated` | curator | `added`, `updated`, `deleted`, `episode_saved` |
| `usage.updated` | system | `usage: RunUsage` (throttled to at most 1 per second) |
| `budget.warning` | system | `resource` (`cost`, `fetches`, `tokens`, `time`), `used`, `limit` |
| `budget.exhausted` | system | `resource`, `action` (`proceeding_to_write`) |
| `run.completed` | system | `report_available: true`, `usage` |
| `run.failed` | system | `error_code`, `message` (sanitized, no secrets or stack traces) |
| `run.cancelled` | system | `phase` |

Optional later (Phase 13): `report.delta` for streaming the Writer's text.

## 5. Response models (summary)

```python
class RunSummary(BaseModel):
    id: UUID; question: str; depth: Depth; status: RunStatus; phase: Phase | None
    created_at: datetime; started_at: datetime | None; finished_at: datetime | None
    cost_usd: float; accepted_findings: int; sources_used: int

class RunDetail(RunSummary):
    plan: ResearchPlan | None; report: Report | None
    usage: RunUsage; budget: Budget; error: str | None; use_memory: bool
```

## 6. Behavior details

- **Create run:** validate, apply depth preset and bounded overrides, insert row, register the task, return 202 immediately. A budget override above the server maximum returns 422 with a clear message.
- **Cancel:** sets a cancel flag and cancels the task; the orchestrator emits `run.cancelled`, saves partial state, and never writes a report afterwards.
- **Delete:** only for finished runs (409 otherwise).
- **Report Markdown:** `[n]` markers become footnote-style links with the references list including source title, domain, and fetch date.
- **Idempotency:** `POST /v1/runs` accepts an optional `Idempotency-Key` header; the same key within 24 hours returns the original run.

## 7. Contract tests

- Use `httpx.AsyncClient` with the ASGI app and a fake orchestrator for fast route tests.
- SSE test: start a fake run that emits N events; assert ordering, `id` lines, replay with `Last-Event-ID`, no duplicates, and clean close on a terminal event.
- OpenAPI snapshot test: `openapi.json` committed equals generated.
- Auth test: every non-health route returns 401 without a valid key.
- User isolation test: a second user's token cannot read or cancel the first user's run.
